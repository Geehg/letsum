# LETSUM 리서치 v2 — 국내·해외 폰트 서비스 벤치마크와 리디자인 근거

작성일 2026-10-11 · 대상: letsum.app 시안 (14종 OFL 데모 데이터)

## 0. 결론 먼저

- **문제**: v1 시안은 눈누의 정보 구조를 그대로 따랐다. "문구 입력 → 흰 카드 격자 → 카드 클릭 → 상세에서 라이선스 표". 기능(라이선스 필터·타입 테스터·서브셋)을 더 얹어도 **화면의 첫인상과 사용 흐름이 눈누와 같아서** 차별화가 체감되지 않았다.
- **방향**: 리서치 v1(muse.ai)의 결론 "카탈로그가 아니라 한글 작업대"를 **화면 구조 자체**로 옮긴다. 해외 선도 서비스가 공통으로 쓰는 "전역 컨트롤 + 큰 견본(specimen) 목록" 구조를 기반으로, 한글에서만 가능한 검증 기능을 목록 단계에 넣는다.
- **차별화 한 줄**: 눈누는 "폰트를 보여주는 곳", LETSUM은 "**내 문장·내 쓰임새로 폰트를 검증하는 곳**".

## 2. 왜 눈누와 같아 보였는가 (v1 진단)

1. **같은 단위**: 흰 카드 1장 = 폰트 1종, 카드 안에 문구·이름·제작자. 눈누와 동일한 시각 단위.
2. **같은 순서**: 큰 히어로 → 문구 입력 → 칩 필터 → 카드 격자. 눈누의 첫 화면 리듬.
3. **같은 색 문법**: 흰 바탕·파란 포인트·둥근 모서리(14px) — 국내 SaaS 기본 톤.
4. **검증 기능이 상세 뒤에 숨음**: 타입 테스터·옛한글·한자 검출이 모달 안에만 있어 목록에서는 차별화가 보이지 않음.

## 3. 리디자인 원칙

- **견본이 주인공**: 종이색 바탕(#f4f2ec)에 먹색 괘선, 모서리 0. UI는 라벨과 선만. 포인트 색은 라임 한 가지(허용 ✓, 큐레이션 강조)만 쓴다. 그라데이션·그림자 없음.
- **전역 컨트롤 데크**: 문장(프리셋 7종: 본문/제목/자소 전체/겹받침·희귀자/영문·숫자 혼용/옛한글/한자 혼용)·크기·굵기·반전·영문 짝꿍이 **모든 행에 동시 적용**. 스크롤해도 고정.
- **목록 기본, 격자·맥락 선택**: 목록은 Fontshare식 큰 견본 행(이름·제작자·굵기·글자 범위 | 견본 | 라이선스 알약·행동). 격자는 밀도용. 맥락은 쓰임새 프레임.
- **검증을 목록 단계로**: 글자 누락·옛한글·한자 지원이 행에서 바로 보인다.
- **제목은 세리프(함렛)**: 눈누·국내 SaaS의 고딕 UI와 다른 편집 디자인 인상.

## 4. 한글 특화 기능 — 구현 완료 (이번 커밋)

| 기능 | 왜 한글에서만 의미 있나 | 구현 방식 |
|---|---|---|
| **내 문장 글자 누락 검사** | 손글씨·디스플레이 한글 폰트 상당수가 2,350자(KS X 1001)만 지원. "뷁·똠·햏" 같은 글자, 상호·신조어가 빠지면 □로 깨진다. 라틴 서비스엔 없는 문제 | 캔버스에 대상 폰트와 한글 없는 라틴 폰트(Inter)로 같은 글자를 그려 픽셀 비교. 같으면 시스템 대체 폰트로 그려진 것 = 누락. 행 견본에서 누락 글자를 빨갛게 표시, "모두 지원하는 폰트만" 필터 |
| **옛한글·한자 자동 검출** | 국학·출판·학술 수요. 사전 데이터 없이도 판정 | 위 검출기로 'ᆞ·ᄒ', '漢·國' 프로브 → 글자 범위 태그와 필터 |
| **글자 범위 태그** | 11,172 완성형 / 2,780 / 2,350 — 일본 FONT FREE의 문자 세트 아이콘에 해당 | 데이터 필드 `cov` + 자동 검출 결과를 행·카드·비교에 표기 |
| **초성 검색** | 한글 입력기의 관습. "ㄱㅇㄷㄷ" → 고운돋움 | 음절을 초성으로 분해해 매칭 |
| **한글-라틴 영문 짝꿍** | 한글 폰트의 영문·숫자가 약한 경우가 많아 실무에서 영문만 다른 폰트를 섞는다 | `font-family: 라틴, 한글` 순서로 영문만 라틴 폰트가 맡게 렌더링. 폰트별 추천 짝(Inter/Space Grotesk/Playfair/Plex Mono), 데크 토글·상세 선택·임베드 코드까지 |
| **맥락 보기 6종** | 썸네일·책 본문·자막·메뉴판·카드뉴스·UI — 한국 콘텐츠 제작자의 실제 작업 단위 | CSS 프레임에 현재 문장·굵기를 주입. 메뉴판은 숫자·가격, 책 본문은 장문 조판, 자막은 반투명 바 |
| **겹받침·희귀자 프리셋** | 자소 조합 품질 확인 | TEXT_PRESETS |
| **상황별로 시작** | 산돌구름 PICK의 질문형 추천을 한 번의 클릭으로 | 분류+맥락+문장 동시 적용 |
| **유료 폰트 대신** | 국내 검색 의도의 큰 축("○○ 대신 쓸 무료 폰트") | ALTERNATIVES 목록 → 해당 폰트만 표시 |
| **비교 트레이** | 최종 후보 2~4종을 같은 조건으로 | 하단 고정 트레이 → 나란히 보기 모달(문장·크기·자간·행간·반전) |

## 5. 운영 원칙 — 사용자 대상 AI 기능 없음

유지비를 감당할 수 없으므로 **사용자가 쓰는 기능에 AI(모델 호출)를 두지 않는다.** 모든 기능은 정적 파일(nginx) + 브라우저 계산으로 끝나야 한다. 서버 비용은 NAS 전기세뿐이어야 한다.

| AI로 하기 쉬운 것 | LETSUM의 대체 기술 | 상태 |
|---|---|---|
| 비슷한 폰트 추천 | **브라우저 캔버스 측정**: '가나다' 잉크 밀도(굵기), 글자폭(너비), ㅡ/ㅣ 획 두께 비(대비)를 재서 거리 계산. 분류가 다르면 거리 가산 | 구현 (상세 모달 "닮은 폰트") |
| 이미지로 폰트 찾기 | 위 측정값을 **정적 JSON으로 사전 계산**(fontTools로 빌드 시) → 사용자가 굵기·너비·대비 슬라이더로 좁히기(Google Fonts의 Properties 필터 방식). 사진 인식은 하지 않음 | 다음 단계 |
| 분위기·용도 태깅 | 검수자가 데이터 필드(`mood`, `tags`)에 수동 입력. 큐레이션은 사람이 | 구현 |
| 질문형 추천(PICK) | **규칙 테이블** 기반 용도 마법사: 용도 → 필터 조합·맥락·주의사항을 정적 JSON으로 | 다음 단계 |
| 폰트 조합 추천 | 제작자·검수자가 입력한 `pair` 필드 + 규칙(제목 디스플레이 × 본문 명조/고딕) | 구현(영문 짝꿍) / 확장 예정 |
| 글자 누락·옛한글·한자 판정 | 캔버스 픽셀 비교(사전 데이터 불필요) | 구현 |
| 검색 | 초성 분해·태그 매칭(클라이언트) | 구현 |
| 서브셋 | Google Fonts unicode-range 재조합(클라이언트) | 구현 |

## 6. 다음 단계 (우선순위)

1. **실데이터 확장(핵심)**: 500종+ 수집 시 `cov`(글자 수)·굵기·라이선스 매트릭스를 검수 테이블로. 자동 검출은 참고용 보조로 유지.
2. **속성 슬라이더 찾기**: 빌드 시 fontTools로 굵기·너비·대비·x높이를 계산해 `metrics.json`으로 배포 → 슬라이더 필터 + "닮은 폰트" 정확도 향상. (이미지 검색의 비용 0 대체)
3. **용도 질문 마법사(규칙 기반)**: "어디에 쓰나요?"(유튜브/로고/인쇄/앱 임베딩/전자책/포장) → 필터+맥락+주의사항.
4. **조합(Pairs) 1차 메뉴**: 제목 한글 × 본문 한글 × 영문 짝꿍 저장·공유. 저장은 URL 직렬화(서버 없음).
5. **공유 링크·즐겨찾기 폴더**: URL 상태 직렬화 → 팀 공유.
6. **라이선스 변경 알림**: 즐겨찾기 폰트의 매트릭스가 바뀌면 메일(기존 원닷 문의 메일 서버 재사용, 정적 사이트는 유지).
7. **제작자 생태계**: 후원·입점·"이 폰트가 쓰인 곳" 제보.
