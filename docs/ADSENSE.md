# LETSUM AdSense 운영

2026-11-06 준비. 게시자 ca-pub-7515626837780401 (공개 식별자), 광고 단위 LETSUM_guide_bottom_responsive / 1602264730.

## 현재 배포 구조

- tools/state/adsense.json이 승인 상태·광고 활성화·CMP 게시 여부·개인정보 공지 적용 시점·허용 페이지를 관리한다.
- build_adsense.js는 재생성되는 페이지에 소유 확인용 메타만 넣는다. 광고가 꺼져 있으면 광고 스크립트·광고 영역을 생성하지 않는다.
- 승인 + CMP 게시 + 2026-11-13 00:00 KST 이후 + adsEnabled=true가 모두 필요하다. 날짜만 지나도 자동으로 켜지지 않는다.
- 초기 광고 대상은 guide.html 하단 1개. 홈 검색 결과, 폰트 카드/다운로드 버튼, 상세 모달, 관리자, 로그인, 법적 안내, 필사 앱은 광고 대상이 아니다.
- 실제 활성화 후에도 localhost, query/hash가 있는 URL, DNT/GPC 사용 환경에서는 로더가 Google에 요청하지 않는다.
- 광고는 접근 시 지연 로딩한다. 광고 표시와 최소 높이로 콘텐츠와 분리한다. 광고 미충전 시 광고 프레임을 조작하거나 재요청하지 않는다.
- Google CMP는 계정에서 letsum.app만 선택해 게시해야 한다. 자체 동의 팝업은 Google 인증 CMP의 대체가 아니다.

## 승인 후 활성화 순서

1. 사이트 상태가 준비됨인지 확인한다. 심사 중이나 거절이면 siteApproved를 켜지 않는다.
2. Google 개인정보 보호 및 메시지에서 letsum.app의 유럽 규정 메시지와 개인정보 URL을 확인한다. 동의·거부·옵션 관리, 철회 경로와 적용 지역을 확인한다. 타 사이트의 설정은 바꾸지 않는다.
3. 11월 13일 이후 현재형 개인정보처리방침(광고 활성화 범위와 실제 CMP 설정 포함)을 갱신한다. 기존 '현재 광고 비활성' 공지와 9항도 갱신해야 한다.
4. config의 siteApproved, cmpPublished, adsEnabled를 사실에 맞춰 변경하고 빌드/검증/배포한다. 자동 광고는 계속 끈다.
5. 실제 광고를 클릭하지 않고 모바일·데스크톱에서 표시, 거부·재동의, 버튼과 간격, CLS, 오류, 미충전 상태를 점검한다. 로컬 레이아웃 검증에서는 Google 광고 요청을 보내지 않는다.

## 운영과 최적화

첫 14일은 한 개 배치를 유지하고 날짜/기기별 페이지뷰·예상 수입·페이지 RPM·광고 노출·조회 가능 노출률을 AdSense에서 비교한다. 자체 방문 통계와 Google 집계 정의는 달라 합산하지 않는다. 적은 표본의 CTR 변화로 성공을 단정하지 않는다.

모바일 레이아웃 이동(CLS 목표 0.1 이하), 페이지 속도(LCP 목표 2.5초 이하), 폰트 검색/공식 배포처 이동 이용률을 함께 본다. 광고 RPM 상승과 핵심 이용률 하락을 함께 평가한다. 배치는 한 번에 하나만 변경한다. 초기 전면/앵커/자동 인페이지 광고는 사용하지 않는다.

관리자·운영자는 자기 광고를 클릭하지 않는다. 광고 클릭 유도, 다운로드 버튼처럼 보이는 디자인, 보상 제공, 자동 새로고침을 하지 않는다. 부정 트래픽/정책 경고가 있으면 adsEnabled=false로 긴급 중지 후 재빌드·배포한다. 수입이나 승인 시점을 보장하지 않는다.
