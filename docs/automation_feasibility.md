# 무료 폰트 라이브러리 자동 수집·갱신 — 타당성 조사

작성일 2026-10-11 · 전제: 유지비 0원(외부 유료 API·AI 없음), 정적 사이트 유지

## 0. 결론

- **"발견·메타데이터·변경 감지"는 자동화 가능, "라이선스 해석·공개 여부"는 사람이 해야 한다.** 무료 폰트의 핵심 가치가 "쓸 수 있는 범위"인데, 그 범위는 배포처마다 자연어 안내문으로만 제공되고 바뀌기도 한다. 자동으로 사이트에 올리면 틀린 범위를 공신력 있게 내보내는 꼴이 된다.
- 따라서 구조는 **자동 감시 → 관리자 검수 큐 → 승인 시 데이터 반영**이다. 감시는 GitHub Actions(공개 저장소 무료) 또는 NAS 크론으로 매주 돌리고, 변경이 있으면 GitHub 이슈로 알림(메일)이 온다. 프로토타입 `tools/watch_sources.py`를 만들어 실제로 돌렸다.
- 기계가 읽을 수 있는 배포처는 **Google Fonts(한글 38종)·Fontsource(39종)·GitHub 릴리스·공공데이터포털(안심글꼴 328행)** 이다. 눈누·산돌구름·폰트코·개별 기업 전용서체 페이지는 API가 없고, 약관상 자동 수집이 안전하지 않아 **사람이 보는 발견 채널**로만 쓴다.

| **Fontsource** | `api.fontsource.org/v1/fonts?subsets=korean` | 전부(Google 미러 + npm 버전) | 수시 | 0 | 서브셋 제공 폰트의 npm 설치 경로 자동 생성에 사용 |

## 2. 자동화할 수 있는 것 / 없는 것

**자동화 가능 (프로토타입에 포함)**
- 새 패밀리·새 릴리스·굵기 변경·사라진 폰트 감지 (Google Fonts, Fontsource, GitHub)
- 공공 목록 페이지 변경 감지 (해시 비교)
- 사이트 데이터 반영 후보 생성: 이름·영문명·분류·굵기·제작자·배포 URL·수정일

**자동화 가능 (다음 단계, 빌드 시 1회 계산)**
- 폰트 파일을 받아 **fontTools**로 한글 글자 수(2,350/11,172), 옛한글·한자 포함 여부, 굵기 축, 측정값(굵기 밀도·너비·대비)을 `metrics.json`으로 생성 → 브라우저 추정을 정확한 값으로 교체
- 공공데이터포털 목록을 받아 공공누리 유형별 라이선스 매트릭스 템플릿 자동 채움(검수자 확인 후 공개)

**자동화하지 않는 것 (원칙)**
- 자연어 라이선스 안내문 해석 → 매트릭스 작성. 사람이 원문을 읽고 작성, 검수일 기록
- 사이트 공개. 검수 큐에서 승인한 항목만 `data.js`로 내보냄
- 눈누·산돌구름·폰트코 등 상업·편집 서비스의 데이터 수집

## 3. 수집 자산 구조 — 여러 루트, 하나의 카탈로그

보고서만 남기면 자산이 되지 않는다. `tools/watch_sources.py`는 루트별 스냅샷을 **카탈로그(`tools/state/catalog.json`)에 병합·누적**한다. 레코드는 지우지 않고, 루트에서 사라지면 `gone` 날짜만 적는다. 저장소에 커밋되므로 이력이 git에 남고, 어느 배포처가 문을 닫아도 수집 기록은 유지된다.

레코드 한 건의 구조:
```
"pretendard": {
  "name": "Pretendard",
  "sources": { "github": {...}, "google": {...}, "fontsource": {...}, "kogl": {...} },   # 루트별 원본
  "first_seen": "2026-10-11", "last_seen": "2026-10-11",
  "history": [ {"date": "...", "event": "🔄 Google Fonts 갱신 ..."} ],                   # 변경 이력 누적
  "license_auto": "OFL" | "공공누리 제1유형" | null,   # 구조화된 원문에서만 자동 판정. null이면 사람이 확인
  "review": "pending" | "approved" | "rejected",      # 사람이 적는 필드 — 자동화가 덮어쓰지 않음
  "site_id": "noto-sans-kr" | null                     # data.js 반영 여부
}
```
- 병합 키는 패밀리명 정규화(소문자·공백 제거). Google Fonts와 Fontsource의 같은 폰트가 한 레코드로 합쳐진다(38종이 2개 이상 루트에서 확인됨).
- `review: approved`인데 사이트에 없는 레코드는 `tools/state/candidates.data.js`로 data.js 초안을 내보낸다(한글명·매트릭스 등 TODO는 사람이 채움).
- 새 루트 추가 = `root_xxx()` 함수 하나와 `merge()`의 두 줄. 공공데이터포털 CSV는 `tools/sources/`에 파일을 두면 `kogl` 루트로 자동 흡수된다.

**운영 흐름 (비용 0원)**
```
매주 월 09:00  GitHub Actions(.github/workflows/watch-sources.yml)
   └ tools/watch_sources.py  →  catalog.json 누적 + sources.json 스냅샷 + report.md
        └ 변경 있음 → 상태 커밋 + GitHub 이슈 생성 → 메일 알림
관리자: 이슈를 보고 원 배포처에서 라이선스 원문 확인 → catalog.json의 review를 approved로
       → candidates.data.js 초안을 채워 data.js에 반영 → 커밋 → "받아와 재배포"
```
- GitHub Actions는 공개 저장소에서 무료. NAS 크론으로 옮겨도 동일(`python3 -I tools/watch_sources.py`).
- 미인증 GitHub API 한도(60회/시간)는 주 1회 저장소 6곳 × 2호출이면 충분.
- 첫 실행(2026-10-11): 카탈로그 45종(Google 38 · Fontsource 39 · GitHub 6), 자동 OFL 판정 41종, 사이트 반영 13종, 검수 대기 45종. 두 번째 실행 "변경 없음" — 페이지 해시 안정 확인.
- Pretendard처럼 GitHub가 라이선스를 판별하지 못하면(`NOASSERTION`) `license_auto`가 비어 사람 확인으로 넘어간다. 의도된 동작.

**파일 자산화(선택)**: OFL·Apache 폰트는 재배포가 허용되므로, 승인 레코드의 원본 파일(GitHub 릴리스 zip, Google Fonts 저장소 TTF)을 NAS에 **비공개 보관**할 수 있다(`tools/archive_files.py`, 다음 단계). 사이트는 계속 원 배포처로 연결하되, 배포처가 사라졌을 때 검수 근거(라이선스 원문·파일 해시)를 잃지 않기 위한 보관이다. 공공누리는 유형별 조건(출처 표시, 변경 금지)을 레코드에 적어 둔 경우만 보관한다.

## 4. 라이브러리 규모 전망

| 공급원 | 자동 등록 가능 | 반자동(목록 자동, 라이선스 사람) | 수동 |
|---|---|---|---|
| Google Fonts 한글 | 38 | | |
| GitHub OFL 한글 폰트 | ~10 | | |
| 공공데이터포털 안심글꼴·공공저작물 | | ~300 | |
| 기업·지자체 전용서체 | | | ~200+ |

→ 초기 500종 목표 중 **약 350종은 목록 자동 수집**, 라이선스 매트릭스는 유형 템플릿(OFL·공공누리 1~4유형) 적용 후 사람이 확인. 나머지는 제보·수동.
