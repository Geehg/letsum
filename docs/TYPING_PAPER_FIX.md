# 필사 용지 이송·줄바꿈 수정 — 2026-10-29

## 재현과 원인

운영자 첨부의 Olympia SM3 / 「별 헤는 밤」을 격리된 Chrome 세션에서 재현했다. 기존 사용자 localStorage·계정·필사 초안은 변경하지 않았다.

1. 1310×863, 기본 14px에서 211번째 입력 시 노출된 종이 높이가 약 471px에서 55px로 줄었다. `row % rowsPerSheet`와 페이지 단위 `feedScroll`이 용지 한계마다 동시에 초기화되어 종이가 아래로 급격히 돌아갔다.
2. 원문의 `↵` 표시가 `inline-block`이면서 본문 전체 line-height를 물려받아, 엔터가 있는 줄의 실제 행 높이가 약 38.17px로 늘어났다. 이송은 35.17px 고정 행 높이로 나눠 반올림했으므로 누적 오차가 생겼다. 일부 줄 끝에서는 계산상 행이 앞뒤로 바뀌었고 기호가 용지 하단에 걸렸다.
3. 줄바꿈 직후 본문 커서는 먼저 다음 줄로 이동하지만 용지가 올라오는 데 180ms가 걸렸다. 그동안 다음 글자가 아직 드러나지 않은 영역에 들어갈 수 있었다.
4. 소리 엔진이 줄 폭 86%에서 미리 벨을 울렸다. 별도 기계 엔진에도 같은 마진 이벤트가 남아 있었다. 이는 사용자가 요청한 실제 줄 전환 시점과 다르다.

## 수정

- `typing-paper-layout.js`: 실제 원문의 DOM Range로 다음 글자의 좌표를 측정. 줄바꿈은 작은 화살표 대신 본문 폰트의 실제 개행 텍스트 노드를 측정한다. 캐리지·종이·알림이 같은 행 좌표를 사용한다.
- `typing-retro-focus.css`: 개행 기호의 line-height를 제한해 본문 행 높이를 늘리지 않게 하고, 원문에는 브라우저의 스크롤 앵커 보정을 적용하지 않는다.
- `typing-hermes.js`: 모듈로 기반 새 종이 초기화를 제거. A4 노출 높이를 채운 뒤에는 용지 위치를 유지하고 초과 본문만 연속으로 올린다. 실제 페이지 이동 때는 정상적으로 첫 줄로 돌아간다.
- 이송 애니메이션 동안 아직 드러나지 않은 높이를 원문 스크롤로 보상한다. 렌더링 프레임에서 종이 높이·에디터 높이·스크롤을 함께 적용해 다음 글자가 용지 하단에서 사라지지 않게 한다.
- `typing-audio.js`: 86% 사전 벨을 제거. 확정된 엔터 또는 실제 자동 줄 전환에서만 벨과 복귀음을 한 번 재생한다. IME 중 레이아웃 변경이 미확정 줄 전환을 소비하지 않도록 한다.
- 조합 중인 엔터는 `isComposing`뿐 아니라 내부 composition 상태·keyCode 229도 확인하여 캐리지 복귀를 먼저 시작하지 않는다.

## 브라우저 시뮬레이션

`tools/check_typing_paper_browser.cjs`는 사용자가 쓰는 원문 전체 DOM과 실제 타자기 모델을 실행하고, 입력마다 프레임별로 다음 글자의 상하 잘림과 종이 역방향 이동을 검사한다. 소리 출력 장치만 가짜 AudioContext로 대체하여 예약된 음의 종류·입력 위치를 기록한다. 실제 녹음 파일과 동기 재생은 기존 오디오 검사로 별도 검증한다.

| 모델 | 화면 | 글자 크기 | 입력 | 검사 프레임 | 정상 줄 전환 |
|---|---|---:|---:|---:|---:|
| Olympia SM3 | 1310×863 | 14px | 390자 | 733 | 24 |
| Hermes 3000 | 1440×900 | 14px | 390자 | 720 | 23 |
| Lettera 32 | 1280×800 | 18px | 390자 | 759 | 26 |
| Olympia SM3 | 1310×863 | 28px | 390자 | 837 | 32 |
| Olympia SM3 | 390×844 | 14px | 390자 | 798 | 29 |
| Hermes 3000 | 768×1024 | 14px | 390자 | 720 | 23 |

합계 2,340자 / 4,567프레임. 다음 글자 상하 잘림 0, 순방향 입력 중 종이의 하향 점프 0px. 157번의 실제 줄 전환에 벨·복귀음이 각각 정확히 한 번씩 일치했다. 마지막 391번째 글자 입력과 다음 페이지 전환은 아래 별도 상호작용 검사에서 확인했다. 휴대폰·태블릿은 Chrome 뷰포트 에뮬레이션이며 실물 iOS/Android 또는 Safari 테스트가 아니다.

`tools/check_typing_paper_interactions.cjs` 추가 확인:

- 실제 브라우저 Enter/Backspace: 개행 경계 5곳에서 3회씩 반복.
- Enter 뒤 첫 한글의 실제 입력, 다음 예시 글자 및 포커스 유지.
- 한글 compositionstart/input/compositionend와 조합 확정 Enter(keyCode 229, isComposing false).
- 창 크기 1024×768 → 768×1024 → 1310×863 변경, 초안 보존.
- 실제 종이 이송 ON/OFF, 본문/현재 글자 유지.
- 한 쪽 완료 및 다음 쪽 첫 글자/스크롤 0 복귀.

## 회귀 검사와 버전

- `check_typing_audio.mjs`: 조기 벨 없음, 실제 개행·자동 줄 전환, IME/resize 중 전환 보존, 중복 타건 방지, 녹음 10종, 동기 재생·음소거·재개.
- `check_typing_hermes.mjs`와 `--lettera`, `--olympia`: 기존 기계·모델·IME·페이지·구도·장애 복구 검사, 누적 1,100자 입력 중 용지 높이 단조 증가/상한 검사 추가.
- 필사 시작·포커스 및 도트레트로 회귀 검사 통과.
- 전체 validate 오류 0, 기존 경고 264.
- 자산: `typing-paper-layout.js?v=1`, `typing-audio.js?v=3`, `typing-hermes.js?v=52`, `typing-retro-focus.css?v=10`.
- 화면 원본은 `tools/typing_app.html`, 생성물은 `node tools/build_pages.js`의 `html/type/index.html`.

브라우저 검사는 `PLAYWRIGHT_MODULE`로 설치된 Playwright 경로를 지정할 수 있고, `TYPEBOOK_URL`로 검사할 로컬 서버 주소를 바꿀 수 있다. 테스트는 매번 격리된 새 브라우저 저장소를 사용한다.
