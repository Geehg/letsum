# Codex 구현 인계

버전 0.1.0 · 2026-11-09

## 1. 이 인계가 해결한 것

기획을 실제 편집 가능한 화면·데이터·검수 로직으로 옮겼습니다. 이 프로젝트만으로 로컬 검색 디렉터리를 실행하고, 자료 정보를 대조하고, 수정 제안을 JSON으로 내보내고, 검증 후 원본 JSON에 반영할 수 있습니다.

정적 빌드 32개, 공개 시드 30개, 고유 기관 28개, 출처 페이지 36개가 포함됩니다. 세부 수량은 `data/`와 검증 보고서가 기준입니다.

현재 LETSUM의 실제 소스 저장소·기술 스택·운영 자격증명·DB 구조·배포 설정은 제공받지 않았습니다. 따라서 특정 프레임워크나 DB 서비스에 맞춘 가짜 연결, 미검증 배포 주소, 관리자 로그인 모형을 만들지 않았습니다. 운영 환경에 필요한 선택은 실제 저장소 확인 후 진행합니다.

## 2. 기능 경계

| 영역 | 이번 구현 | 운영 전 후속 작업 |
| --- | --- | --- |
| 정보 탐색 | 검색·초성·다중 토큰·필터·정렬·그리드/리스트·빈 상태 | 실제 브라우저 검수, 운영 URL, 데이터 증가 시 검색 성능 |
| 상세정보 | 자료 안내·사용 조건·출처·확인 범위·관련 서체 | 실제 폰트 ID 연결, 근거별 버전 관리 |
| 보관함 | 기기 내 저장, 링크 목록 JSON | 계정 동기화가 필요할 때 인증·DB |
| 제보 | 입력 검사, 미검수 제보 파일 생성 | 접수 API·DB·운영자 알림·스팸 방지 |
| 검수 | 로컬 초안·diff·패치·CLI 검사·감사 보고 | 인증·권한·동시 편집·승인/게시 경로 |
| 출처 상태 | 읽기 전용 검사기, 실패 유형 구분 | 작업 스케줄러, 검수 큐, 제한된 네트워크 실행 |
| 로고 파일 | 공식 안내 메타데이터만 표시 | 권리 확인, 실제 바이너리 검증, 필요한 경우에만 저장 |
| 이미지 | 기관명 텍스트 카드 | 미리보기 허용 근거를 확보한 자산만 표시 |
| SEO | 제목·설명·상세 정적 본문 | 실제 route/canonical/sitemap/robots/검색 노출 정책 |
| 배포 | 로컬 서버와 정적 파일 | 실제 대상 환경에서 stage→검증→승인된 배포 |

## 3. 첫 실행

```bash
npm run validate
npm test
npm run build
npm start
```

`http://127.0.0.1:4173`을 열고 `docs/BROWSER_QA.md`를 수행합니다. 원본 환경에서는 브라우저의 로컬 서버 연결과 file URL이 제한되어 실제 화면 검수를 수행하지 못했습니다. 이 문제를 자동 fixture 테스트로 검증 완료한 것처럼 보고하지 마세요.

## 4. P0: 바로 이어 할 작업

### LSM-001 — 실제 브라우저 검수와 수정

- 데스크톱 1440px, 태블릿 768px, 모바일 390px·360px에서 검수합니다.
- 검색→필터→상세→보관→보관함→내보내기, 검수→수정→패치 내보내기의 전체 흐름을 확인합니다.
- 키보드만으로 조작하고, 화면 재렌더 후 포커스가 유지되는지 확인합니다.
- 콘솔 오류, 잘림, 표 스크롤, 링크 새 탭, 저장소 사용 불가, 뒤로/앞으로 이동을 기록합니다.
- 완료 기준: 실제 브라우저·뷰포트·행동·결과가 기록되고 차단성 오류가 없습니다. 확인하지 않은 브라우저를 지원 검증 완료로 표시하지 않습니다.

### LSM-002 — 기존 LETSUM 저장소에 이식

- 저장소가 제공되면 먼저 라우터, 스타일 토큰, 공통 헤더, 빌드·테스트·배포 명령을 확인합니다.
- 공유 데이터/검색 로직을 유지하고 화면을 기존 컴포넌트 체계로 옮깁니다.
- 기존 폰트 서비스의 명칭·항목 ID·검색 방식·보관함 모델을 확인합니다.
- 이전 기획에 나온 서브도메인은 제안입니다. 소유·DNS·인증서·배포 권한을 확인하기 전 운영 주소로 사용하지 않습니다.
- 완료 기준: 기존 폰트 동작 회귀 없음, 새로운 로고 경로 정상, 기존 테스트 통과, 변경 diff 검토 가능.

### LSM-003 — 데이터 영속화와 근거 분리

- `docs/PRODUCTION_MODEL.md`의 데이터 관계를 실제 DB 방식에 맞춰 구현합니다.
- 공개 필드와 운영 메모·개인정보·승인 이력을 분리합니다.
- 현재 flat JSON을 유실 없이 변환하고 원본 ID를 보존합니다.
- 기관 수, 정체성 수, 버전 수, 자료 수가 각각 중복 없이 집계되는지 검증합니다.
- 완료 기준: 마이그레이션의 입력·출력 레코드 수/ID/참조 대조, rollback 경로, 공개 API에 비공개 필드가 포함되지 않음.

### LSM-004 — 운영자 인증과 게시 권한

- 실제 기존 인증 방식을 재사용합니다. 로컬 검수 화면을 비밀번호 없는 관리자 서버로 공개하지 않습니다.
- 출처 편집, 근거 추가, 검수 완료, 게시/보관을 구분하고 서버에서 권한을 검사합니다.
- 여러 사용자가 같은 레코드를 바꿀 때 버전/해시 충돌을 거부합니다.
- 완료 기준: 비인증 쓰기 거부, 권한 없는 게시 거부, 수정자·시각·이전값·근거 감사 기록, 동시 편집 충돌 테스트.

### LSM-005 — 제보 접수

- 현재 제보 JSON 형식을 받아 서버에서 URL·길이·분류를 다시 검증합니다.
- 제보는 미검수 큐에 들어가며 바로 공개 레코드로 반영되지 않습니다.
- 개인정보는 필요한 경우만 수집하며 불필요한 연락처 입력을 강제하지 않습니다.
- 접수 성공은 실제 서버 응답 후 표시하고 실패 시 재시도 가능한 상태를 제공합니다.
- 완료 기준: 정상 접수, 중복/스팸 제어, 실패 처리, 검수 큐 노출, 공개 자동 게시 없음.

### LSM-006 — 운영용 URL과 배포

- 최종 도메인과 정적/SSR 방식을 실제 운영 환경에서 정합니다.
- 해시 링크 대신 고유 상세 URL을 배포 프레임워크에 맞게 연결하고 404·이전 slug redirect를 구현합니다.
- canonical, sitemap, robots, 공유 메타데이터를 실제 검증된 주소로 생성합니다.
- 검수 화면·내부 데이터·운영 메모는 공개 검색 노출에서 분리합니다.
- 완료 기준: stage에서 직접 새로고침한 상세 URL·한글 검색·외부 링크·리다이렉트·404 정상, 공개 페이지에 비공개 데이터 없음, 실제 롤백 방법 확인.

## 5. P1: 운영 효과를 확인한 뒤 확장

| 작업 | 시작 조건 | 완료 기준 |
| --- | --- | --- |
| 출처 100개 파일럿 | 30개 레코드 검수 흐름 안정 | 우선 카테고리의 실제 확인 데이터 증가, 중복/미확인 비율 기록 |
| 공식 로고 미리보기 | 표시 범위에 대한 근거 확보 | 자산별 출처·근거·확인일·변형 금지 규칙 기록 |
| 계정 보관함 | 기기간 공유 수요 확인 | 권한 경계, 데이터 동기화·삭제, 내보내기 |
| 검색 인덱스 | 실제 지연 또는 규모 문제 확인 | 기존 초성/별칭/AND/형식 검색 회귀 없음 |
| 변경 감지 | 공식 출처 검사 작업 안정 | 내용 변화가 검수 큐로 들어가며 자동 권리/버전 승격 없음 |
| 광고·유료 기능 | 사용과 운영비 데이터 축적 | 사실에 근거한 정책·측정, 다운로드 권한과 광고 구분 |

예정 출시일·수익·검색 유입 규모는 이번 코드로 검증하지 않았습니다. 숫자 목표는 작업 계획으로만 취급합니다.

## 6. 데이터 편집 계약

정확한 필드·enum은 `schemas/`와 `docs/CONTRACT.md`가 기준입니다.

- 현재 `records[]` 한 항목은 단일 아이덴티티와 그 자료 안내를 묶은 인계용 뷰입니다.
- 기관의 대표 분류는 하나이며 분야는 복수입니다.
- `source-reviewed`는 출처 확인 범위 기록입니다. 게시 권한, 현행, 바이너리, 라이선스 확정을 뜻하지 않습니다.
- `source_scope=search`와 `page`를 다르게 표시합니다.
- 형식 미표시 다운로드는 `page-listed`와 빈 `listed_formats`를 함께 가질 수 있습니다.
- `download_url`은 확인한 실제 링크만 입력하고, `file-verified`는 직접 받은 파일의 검증 메타데이터와 함께 사용합니다.
- 과거 버전과 기관명 변경을 삭제로 처리하지 말고 이력·관계로 보존합니다.

## 7. 검증 명령의 의미

`npm run validate`: JSON 구조, enum, ID, 출처 참조, URL, 파일 메타데이터, 근거/상태 불변식 검사입니다. 실제 원문 내용이 정확하다고 자동 인증하지 않습니다.

`npm test`: 검색과 필터, 악성 입력, 출력 이스케이프, 데이터 상태, CLI 경계, 빌드, HTTP 응답을 검증합니다. 일부 공개 UI 테스트는 최소 DOM fixture와 VM을 사용합니다. 화면 렌더링 엔진·실제 브라우저 다운로드·시각적 대비의 종합 검사와는 다릅니다.

`npm run check-links`: 읽기 전용 HTTP 응답 검사입니다. 실패 상태를 삭제 사유로 자동 변환하지 않습니다. 공개 제출 URL을 서버에서 무제한 가져오는 기능으로 재사용하지 마세요.

## 8. 패키지 전달 이후 변경 관리

- 원본 패키지의 SHA-256은 배포 무결성 확인용이며 수정 후에는 달라지는 것이 정상입니다.
- 패치 해시는 파싱한 카탈로그의 JSON 직렬화 기준입니다. 파일용 해시와 혼동하지 않습니다.
- `dist`는 생성물입니다. 소스 변경 뒤 검증·빌드하고 최종 배포물을 다시 확인합니다.
- 이전 기획 파일은 `reference/`에 보관합니다. 구현상 정정 사항은 `docs/STATUS.md` 및 `docs/CONTRACT.md`를 우선합니다.

## 9. 개발 완료 보고 형식

기능 변화, 실제 수정 파일, 검증 명령과 결과, 실제 브라우저 검수 결과, 원문 확인 범위, 미완료 연결·배포 항목을 한국어로 보고합니다. mock·fixture·실데이터·네트워크 검사를 구분하세요. 요청되지 않은 운영 배포나 메시지 발송을 완료한 것으로 표현하지 마세요.
