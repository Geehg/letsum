# 로컬 검수 도구

이 문서는 `src/review.js`와 `src/review.css`가 제공하는 검수 화면의 사용 범위와 패치 계약을 설명합니다. 화면은 빌드된 `dist/review.html` 또는 `#/review` 경로에서 열립니다.

## 구현 범위

- 원본 레코드 목록과 원본 검수 상태 필터, 이름·기관·ID 검색을 제공합니다.
- 레코드의 공통 출처, 원문 링크, 출처 확인 범위와 날짜를 보여 줍니다.
- 허용한 텍스트·분류 필드만 편집하고 원본과 수정안의 차이를 보여 줍니다.
- 레코드별 검토 메모와 수정 초안을 브라우저에 보관하고 패치 JSON으로 내보냅니다.
- 로고 이미지 미리보기, 원본 카탈로그 직접 수정, 서버 저장, 자동 게시 기능은 없습니다.
- 서버 인증·권한 관리·데이터베이스·운영자 협업 잠금은 구현하지 않았습니다. 이 페이지는 공개된 검토용 데이터에 대한 로컬 도구이며 운영용 관리자 시스템이 아닙니다.

## 사용 순서

1. 레코드를 선택하고 공식 자료·가이드·정책 링크를 새 탭에서 확인합니다.
2. 필드별 근거 대조표에서 원본 값과 출처의 일치 여부를 확인합니다.
3. 허용 필드를 수정하고 검토 메모에 확인한 내용·남은 항목·원문 위치를 적습니다.
4. 원본과 수정안 비교를 읽고 입력 형식 오류를 해결합니다.
5. **수정안 JSON 내보내기**를 누릅니다. 현재 목록 필터와 관계없이 모든 로컬 초안과 메모가 파일에 포함됩니다.
6. Codex 또는 담당 개발자는 패치 가져오기 CLI의 기본 dry-run 결과를 검토한 후 명시적 로컬 쓰기 옵션으로 반영합니다. 정확한 명령은 프로젝트 README와 가져오기 스크립트 도움말을 따릅니다.
7. 적용된 변경 내용의 공식 근거를 재검수합니다. 패치 적용 자체는 공개 배포나 권리 승인 완료를 뜻하지 않습니다.

브라우저는 다운로드 요청의 완료 여부를 코드에 확정적으로 알려 주지 않습니다. 화면은 다운로드를 요청했다는 사실만 표시하며, 원본·서버에 적용됐다고 표시하지 않습니다. 내려받기 이후에도 로컬 초안은 남습니다.

## 편집할 수 있는 필드

`name`, `name_en`, `aliases`, `category`, `kind`, `sectors`, `country`, `region`, `summary`, `source_url`, `guideline_url`, `usage.summary`만 편집합니다.

- `review_note`는 카탈로그 필드가 아니라 패치에 동봉하는 검토 메모입니다.
- 별칭은 한 줄에 하나씩 입력하며 공백 줄과 중복을 제거합니다.
- 국가 코드는 입력 시 2자리 대문자로 정규화합니다. 영문 이름·국가·지역·가이드 URL의 빈칸은 `null`입니다.
- 분야 순서만 달라지고 구성원이 같으면 의미 있는 변경으로 취급하지 않습니다.
- 원문·가이드 URL은 core의 `safeUrl` 규칙을 통과해야 합니다.
- `source_ids`와 `usage.policy_url`은 이 화면에서 편집하지 않습니다. 새 URL이나 사용 조건 요약을 입력한 경우, 원래 근거 연결을 수정값의 검증 근거로 자동 승계하지 않습니다. 공식 근거와 데이터 참조를 개발 단계에서 다시 대조해야 합니다.
- 승인·재배포·미리보기 허용 플래그, 파일 검증 상태·메타데이터, 브랜드 버전 및 검수 완료 상태를 승격하는 컨트롤은 없습니다.

## 검수 상태 무효화

허용 필드의 실제 값이 하나라도 바뀌면 화면은 적용 후 상태를 `needs-review`로 설명하고, 가져오기 CLI가 다음 값을 강제합니다.

```json
{"status":"needs-review","checked_at":null,"source_scope":null}
```

원본의 검수 날짜와 확인 범위를 새 값에 승계하지 않습니다. 패치 자체에는 임의 `review` 필드를 포함하지 않습니다. 바뀐 값 없이 메모만 추가한 패치는 `changes: {}`이며 원본 검수 상태를 유지합니다. 메모는 가져오기 결과·감사 보고서에 보존하는 용도이며 카탈로그의 임의 필드로 추가하지 않습니다.

의미 있는 변경 전의 버전 상태가 `current`였다면, 가져오기 CLI는 기존 현행 확인 근거도 무효화하여 `unconfirmed`로 바꾸고 감사 기록에 이를 남깁니다. 화면의 비교표에서도 이 전환을 표시합니다. 메모만 추가하면 버전 상태도 유지합니다.

입력 형식 검사 통과는 URL 문법과 분류 등 입력 구조에 대한 확인입니다. 사실성·원문 일치·사용허락·재배포 권한 또는 바이너리 검사 완료를 의미하지 않습니다. 최종 스키마·참조 검사는 가져오기 CLI가 수행합니다.

## 근거 표시의 한계

현재 데이터는 레코드 공통 `source_ids`를 보관하며 독립적인 필드별 증거 레코드를 갖지 않습니다. 검수 화면의 표는 이름·분류·지역·소개 등에 대조할 공통 출처를 보여 주는 용도입니다. 해당 출처가 각 필드를 확정적으로 증명한다고 표시하지 않습니다.

기존 권리 조건과 자료 검증 상태는 읽기 전용으로 표시됩니다. 소개 페이지가 살아 있다는 이유로 현행 브랜드로 승격하거나, 공개 다운로드 안내를 실제 바이너리 검사로 승격하지 않습니다.

## 초안 저장

- 저장 키는 `letsum-logo:review:1:{catalogSha256}`입니다. 동일 버전 표기라도 원본 카탈로그 내용의 해시가 달라지면 초안을 자동으로 합치지 않습니다.
- 초안에는 데이터 버전, 원본 해시, 저장 시각, 허용 필드 값과 검토 메모를 보관합니다.
- 사용 가능한 경우 `localStorage`에 쓰고, 실패하면 `sessionStorage`, 둘 다 실패하면 현재 마운트된 화면의 메모리로 보관합니다.
- 저장 결과와 제한을 화면 상단에 표시합니다. 파일 직접 열기 환경에서 저장소의 지속성은 브라우저 설정에 따라 달라질 수 있습니다.
- 로컬 저장 내용도 신뢰하지 않고 알려진 필드와 타입만 읽으며 모든 출력 문자열을 이스케이프합니다.
- **이 항목 초안 지우기**는 선택한 레코드의 로컬 수정값과 메모만 지웁니다. 원본은 변경하지 않습니다.
- 검토 메모도 브라우저 저장소에 남으므로 브라우저 데이터를 삭제하면 잃을 수 있습니다. 다른 기기로 자동 동기화하지 않습니다.

## 패치 JSON 계약

빌드가 계산한 `SHA256(JSON.stringify(catalog))`를 bootstrap의 `catalogSha256`으로 전달합니다. JSON 파일의 원시 바이트 해시가 아닙니다. 브라우저 WebCrypto에 의존하지 않으므로 빌드된 파일을 직접 열어 사용할 수 있습니다. 해시가 없거나 형식이 잘못되면 내보내기를 비활성화합니다.

```json
{
  "schema_version": "1.0",
  "dataset_version": "0.1.0",
  "base_sha256": "빌드에서 제공하는 64자리 SHA-256",
  "created_at": "ISO 8601 UTC 시각",
  "patches": [
    {
      "id": "레코드 ID",
      "changes": {
        "name": "수정한 표시 이름",
        "usage": {"summary": "수정한 사용 조건 요약"}
      },
      "review_note": "수정 이유와 확인한 공식 근거"
    }
  ]
}
```

위 블록은 형식을 설명하는 예시이며 실제 가져오기용 파일이 아닙니다. 내보낸 실제 파일에는 원본과 다른 필드만 들어갑니다. `usage`의 변경 허용 키는 `summary` 하나뿐입니다. 모든 레코드의 입력 오류가 해결되어야 내보내며, 가져오기 CLI에서 원본 버전·해시·필드 허용 목록·스키마를 다시 검사합니다.

## 보안·접근성 구현 메모

- 데이터와 저장된 초안의 문자열은 HTML 텍스트·속성 출력 전에 이스케이프합니다.
- 외부 링크는 `safeUrl`을 통과한 http(s) URL만 사용하며 `noopener noreferrer`로 새 탭을 엽니다.
- 권한 플래그·파일 검증을 설정하는 UI나 네트워크 쓰기 요청을 만들지 않습니다.
- 폼 label과 fieldset/legend, 키보드 초점 표시, 입력 오류 이동 버튼, 선택 상태 및 상태 안내를 제공합니다.
- 레코드 선택 후 편집 제목으로 초점을 이동하고, 입력 오류가 있으면 해당 필드로 이동합니다.
- 이벤트는 검수 루트에 위임하고 `bindReview`가 반환하는 정리 함수로 해제할 수 있습니다.
