# LETSUM 로고·CI — Codex 구현 인계 프로젝트

**버전 0.1.0 · 2026-11-09**

공식 로고·CI 출처를 찾는 실행 가능한 정적 웹앱입니다. 검색·필터·상세정보와 로컬 검수 도구를 포함합니다. 기존 `letsum.app` 운영 소스나 서버는 수정하지 않았습니다.

## 바로 확인하기

완성된 화면 코드는 `dist/index.html`에 있습니다. CSS, JavaScript, 공개 시드 데이터를 한 파일에 포함했습니다. 실제 브라우저의 파일 열기·저장소 정책 차이가 있을 수 있어 아래 로컬 서버 실행을 권장합니다.

```bash
cd letsum-logo
npm start
```

그다음 브라우저에서 `http://127.0.0.1:4173`을 엽니다. 서버 중지는 터미널에서 `Ctrl+C`입니다.

- 요구 환경: **Node.js 22 이상**, Node와 함께 설치된 npm
- 작성·자동 검사 환경: **Node.js 24.22.1 / npm 11.9.0 / Linux**
- 외부 npm 의존성: **0개**. `npm install` 없이 실행합니다.
- 별도 드라이버, DB, API 키, 클라우드 계정: 필요하지 않습니다.
- Node 22의 모든 마이너 버전, macOS·Windows 브라우저의 실제 화면 조작은 이번 환경에서 검증하지 않았습니다.
- 로컬 서버는 `127.0.0.1`에만 바인딩합니다. 공개 운영용 서버가 아닙니다.

## 포함된 화면

| 화면 | 경로 | 동작 |
| --- | --- | --- |
| 찾기 | `#/` | 이름·영문·별칭·초성 검색, 다중 검색어 AND, 형식 검색, 유형·분야·지역·접근 필터 |
| 상세정보 | `#/brand/{id}` | 자료 형식 안내, 승인·재배포·미리보기 조건, 공식 출처, 관련 공식 폰트 |
| 이용안내 | `#/guide` | 확인 상태, 파일 안내와 실제 파일 검증의 차이 |
| 제보 작성 | `#/suggest` | 제보 JSON 생성. 서버 제출 기능 없음 |
| 로컬 검수 | `#/review` 또는 `dist/review.html` | 수정 초안, 원본 대조, 입력 검사, 검수 패치 JSON 내보내기 |

검색 예시: `고양시 AI`, `서울대`, `ㅅㅇㄷ`, `한기대 로고 AI`, `NAVER`, `MIT`.

`dist/brands/{id}/index.html`에는 각 상세정보의 제목·설명·출처 링크를 정적 본문으로도 포함했습니다. 전체 카탈로그와 화면 스크립트를 각 HTML에 포함하는 인계용 구조이며, 운영 전에는 번들 공유·실제 URL 라우팅·캐시 정책을 기존 LETSUM 구조에 맞게 바꾸어야 합니다.

서울시 휘장과 도시 브랜드, NAVER 기업 브랜드와 NAVER API HUB를 같은 기관의 다른 아이덴티티로 기록했습니다. 한국어·영어 공식 자료를 사용했으며 정확한 URL·관측 내용은 `data/sources.json`과 `docs/DATA_REVIEW.md`에 있습니다.

**현재 데이터의 확인 범위**

- 출처 페이지 본문을 확인한 정보입니다. 원본 로고 파일은 내려받거나 포함하지 않았습니다.
- 파일 형식은 공식 페이지의 표시를 `listed_formats`로 기록했습니다. 표시가 없으면 빈 배열입니다.
- 모든 `verified_format`, `size_bytes`, `sha256`, `download_url`은 `null`입니다.
- 모든 로고의 현행 여부는 `unconfirmed`입니다.
- 미리보기 게시 권한은 모두 `unknown`이며, 실제 로고 썸네일도 포함하지 않았습니다.
- 관련 서체는 해당 기관의 공식 배포 관계만 뜻합니다. 로고 적용 서체라는 뜻은 아닙니다.

## 수정하고 검사하기

화면은 `src/`, 데이터는 `data/`를 편집합니다. `dist/`를 직접 수정하면 다음 빌드에서 덮어씁니다.

```bash
npm run validate
npm test
npm run build
npm start
```

`npm run build`는 `dist/`를 재생성합니다. 기본 빌드 결과는 메인 1개, 검수 1개, 상세 30개로 **독립 HTML 32개**입니다. `dist/build-report.json`에 목록과 데이터 해시를 기록합니다.

`schemas/`의 JSON Schema는 실제 코드 검증기와 같은 정의를 사용합니다. 코어 정의를 변경했다면 다음 명령으로 다시 생성합니다.

```bash
npm run schemas
npm run validate
npm test
```

## 검수 화면에서 수정안 반영하기

1. 검수 화면에서 공식 근거를 확인하고 허용된 필드를 수정합니다.
2. 원본과 수정안의 차이, 재검수 필요 상태를 확인합니다.
3. **수정안 JSON 내보내기**를 눌러 파일을 받습니다.
4. 프로젝트 루트에 받은 파일을 두고 먼저 dry-run 합니다. 아래 `review-patch.json`은 받은 파일의 실제 이름으로 바꾸세요.

```bash
npm run import-review -- --file review-patch.json
```

출력된 대상·변경 필드·경고를 확인한 뒤 로컬 파일에 반영하려면 `--write`를 명시합니다.

```bash
npm run import-review -- --file review-patch.json --write
npm run validate
npm test
npm run build
```

의미 있는 변경은 `review.status=needs-review`, 확인일·확인 범위 `null`로 처리합니다. 기존 현행 상태도 `unconfirmed`로 무효화합니다. 메모만 있는 패치는 원본 검수 상태를 유지합니다. 권한·파일 검증·현행 상태를 승격하는 입력은 거부합니다.

`--write`는 **로컬 카탈로그만 변경**하며 `reports/`에 감사 기록을 만듭니다. 운영 서버 게시나 출처 원문 재검수는 수행하지 않습니다. 편집 전의 SHA-256이 다르면 적용을 거부하므로 최신 카탈로그로 다시 내보내야 합니다.

패치의 `base_sha256`는 UTF-8 `JSON.stringify(catalog)`의 SHA-256입니다. 파일 전달용 `SHA256SUMS.txt`의 원시 파일 해시와 계산 대상이 다릅니다.

## 공식 링크 상태 확인

```bash
npm run check-links -- --output reports/source-check-new.json
```

새 보고서 파일 이름을 사용해야 합니다. 기존 파일과 데이터는 덮어쓰지 않습니다.

이 명령은 네트워크 접근이 필요하며 **공식 출처 페이지**만 검사합니다. 원본 파일의 내용·이용허락·현행 버전을 검사하지 않습니다. 403, 429, TLS 문제, 시간 초과는 삭제된 링크로 취급하지 않습니다. 검사 결과는 카탈로그에 자동 반영되지 않습니다.

현재 실행 환경에서는 일반 외부 사이트에 대한 셸 네트워크가 제한되므로, 자동 검사는 독립된 응답 fixture로 분류 로직을 검증했습니다. 실제 출처 내용 확인 기록은 별도의 웹 열람 조사 결과입니다. 링크 검사 CLI가 36곳 모두에 성공적으로 접속했다고 주장하지 않습니다.

## Codex에 인계하기

1. 이 폴더 전체를 Codex 프로젝트에 넣습니다.
2. `AGENTS.md`와 `docs/CODEX_HANDOFF.md`를 먼저 읽도록 합니다.
3. `CODEX_START.txt`의 지시문을 그대로 전달합니다.
4. 기존 LETSUM 저장소가 있다면 실제 프레임워크·인증·배포 구성을 먼저 확인한 후 이식합니다.

서브도메인, DB 제품, 인증 제공자, 운영 배포 환경은 이 코드에서 임의로 확정하지 않았습니다. 제품별 API나 SDK에 의존하지 않는 기능·데이터 규격을 먼저 준비했습니다.

## 이번 인계의 한계

자동 검사·빌드·로컬 HTTP 응답은 확인했습니다. 현재 검증 브라우저가 작업 환경의 로컬 서버에 연결할 수 없고 파일 URL도 허용하지 않아 **실제 브라우저 화면 조작·모바일 레이아웃 검수를 완료하지 못했습니다.** 자동 DOM fixture 검사는 실제 브라우저 검수를 대체하지 않습니다. 구체적인 잔여 항목은 `docs/BROWSER_QA.md`에 있습니다.

서버 DB·운영자 로그인·사용자 계정·제보 접수 API·파일 재배포·이미지 제공·운영 배포는 이번 프로젝트의 구현 범위에 포함되지 않습니다. 다음 구현 순서와 완료 기준은 `docs/CODEX_HANDOFF.md`에 있습니다.

기본 코드에는 라이선스 부여 문구를 임의로 추가하지 않았습니다. 기관·기업·대학의 명칭, 로고, 설명, 링크된 자료의 권리는 각 권리자에게 있습니다.
